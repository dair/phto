## Prioritized Remediation Plan

### Priority 1 — Critical (data integrity, correctness, blocking issues)

These address the riskiest areas: multi-target consistency and the most impactful gaps.

#### 1.1 Multi-target rollback and consistency tests (B6, B7)

**What**: Write integration tests that:
- Set up a 2-target configuration
- Perform writes and verify both databases contain identical records
- Inject failures (e.g., make one DB path read-only mid-operation) and verify rollback/compensation leaves both targets consistent

**Scope**: New test file in `imager/test/`. Requires test infrastructure to simulate storage/DB failures. Estimate: medium effort.

**Why critical**: The all-or-nothing multi-target guarantee is a core architectural promise. It is implemented but unverified under failure conditions.

#### 1.2 Config parser tests (B1)

**What**: Write unit tests for `config/` covering:
- Valid `[[targets]]` config parsing
- Missing file, empty file, malformed TOML
- Missing required fields (root, database)
- Empty targets array

**Scope**: New test file in `config/test/`. Straightforward. Estimate: small effort.

**Why critical**: Config parsing is the entry point for all operations. Silent misparse could cascade.

#### 1.3 Fix sample config (A6)

**What**: Update `imager/sample/config.toml.sample` from obsolete `[storage]`/`[database]` to current `[[targets]]` format.

**Scope**: Single file edit. Estimate: trivial.

**Why critical**: The sample config is actively wrong and would cause parse failures if used.

### Priority 2 — Important (observability, test coverage, documentation)

#### 2.1 Wire DB timing metrics (C4)

**What**: Instrument `database/Database.cpp` read and write methods to record `db_read_duration` and `db_write_duration` histograms via the metrics layer.

**Scope**: Add `metrics::Timer` usage in Database methods. Requires passing a `Metrics&` reference into Database (or a subset). Estimate: medium effort (API change).

#### 2.2 Wire blob lifetime metrics (C5)

**What**: Update `Blob` constructor/destructor to increment/decrement `blobs_alive` and `blob_bytes_alive` gauges.

**Scope**: Requires passing a `Metrics*` (optional) into Blob, or using a global/thread-local registry. Estimate: small-medium effort depending on approach.

#### 2.3 Wire thread pool metrics (C6)

**What**: Update `coro::ThreadPool` to update `pool_queue_depth`, `pool_active_threads`, and `pool_schedule_latency` metrics.

**Scope**: Similar to C5 — requires a metrics reference in ThreadPool. Estimate: small-medium effort.

#### 2.4 Config semantic validation (C7)

**What**: After parsing, reject duplicate `root` paths and duplicate `database` paths across targets.

**Scope**: Small addition to config parser or a post-parse validation step. Estimate: small effort.

#### 2.5 Migrate imagestore to `addFile()` (C1)

**What**: Replace the manual file-reading logic in `imagestore/main.cpp` worker lambda with `img.addFile(path)`. This removes ~30 lines of boilerplate and makes the `read` stage metrics show real data in `--graph` mode.

**Scope**: Modification to `imagestore/main.cpp`. Estimate: small effort.

**Note**: This is also tracked as existing task #12.

#### 2.6 Metrics layer tests (B4, B9)

**What**: Write unit tests for `metrics/` primitives:
- Counter: add, value, reset
- Gauge: increment, decrement, set, value, reset
- Histogram: record, percentiles, reset
- Timer: RAII timing
- Snapshot: format output

**Scope**: New test file in `metrics/test/`. Estimate: small-medium effort.

#### 2.7 Update CLAUDE.md (A1-A5)

**What**: Update the top-level CLAUDE.md to:
- Add `imagestore/` to project structure tree
- List all 8 current test suites
- List all plan documents through 0014
- Update implementation status paragraph
- Fix `docs/plan/` range in tree diagram

**Scope**: Single file edit. Estimate: small effort.

### Priority 3 — Nice to Have (polish, minor improvements)

#### 3.1 Blob and coro tests (B2, B3)

**What**: Write unit tests for `blob/` (construction, shared ownership, freeze semantics) and `coro/` (Task, ThreadPool, whenAll, blockOn).

**Scope**: New test files. `coro/` tests are trickier due to async nature. Estimate: medium effort.

#### 3.2 Storage read failover test (B8)

**What**: Test that `FileStorage::readFile()` falls back to alternative roots when the primary root fails.

**Scope**: New test in `imager/test/`. Requires test setup with multiple roots where one is made unreadable. Estimate: small-medium effort.

#### 3.3 Multi-target sidecar consistency test (B10)

**What**: Verify sidecar relocation and companion records are consistent across all target databases.

**Scope**: Extension of B6 tests. Estimate: small effort (if B6 infrastructure exists).

#### 3.4 Fix `Blob::fromVector()` double-copy (C2)

**What**: Adopt the vector's storage directly instead of copying.

**Scope**: Modification to `blob/Blob.h` or `.cpp`. Estimate: small effort.

#### 3.5 Enforce `Blob::freeze()` (C3)

**What**: Make `writableData()` assert or throw after `freeze()` is called.

**Scope**: Small modification. Estimate: trivial.

#### 3.6 Imagestore CLI tests (B5)

**What**: Test flag parsing, mutual exclusion errors, quiet mode suppression, and error file behavior. Could be shell-script-based or a test harness that invokes the binary.

**Scope**: New test infrastructure. Estimate: medium effort.

**Note**: Consider promoting to Priority 2. `imagestore` is the primary user-facing interface and
has zero test coverage. Any regression in arg parsing or progress reporter mode selection would go
completely undetected by `ctest`.

#### 3.7 Update README.md (A7-A9)

**What**: Fix identity wording (hash-only, not hash+size), fix `validation/` → `validations/`, add mentions of imagestore and expanded format support.

**Scope**: Single file edit. Estimate: small effort.

#### 3.8 Minor code cleanup (C8, C9, C10, C11, C12)

**What**:
- C8: Add a more specific error code for sidecar multi-parent ambiguity
- C9: Improve sidecar rollback atomicity (may require transaction wrapping)
- C10: Document or mitigate the `whenAll()` scheduling invariant
- C11: Move `createDefaultValidators()` to a .cpp file
- C12: Remove unused `sep` variable in `ProgressReporter.cpp:246`

**Scope**: Individual small changes. Estimate: small effort each.

```
Phase A (foundations):  1.2 → 1.3 → 2.4 → 2.7         Config tests, fix sample, semantic validation, update docs
Phase B (integrity):   1.1 → 3.2 → 3.3                 Multi-target tests, failover, sidecar consistency  
Phase C (observability): 2.1 → 2.2 → 2.3 → 2.6         Wire all declared metrics, test metrics layer
Phase D (utility):     2.5 → 3.6                        Migrate to addFile(), add imagestore tests
Phase E (polish):      3.1 → 3.4 → 3.5 → 3.7 → 3.8    Blob/coro tests, Blob fixes, README, minor cleanup
```

Phases A and B should be done first — they address the highest-risk gaps (config correctness, multi-target integrity). Phase C makes the monitoring plan fully realized. Phase D completes the utility. Phase E is polish.
