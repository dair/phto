# 0009 — MOV Video Format Validation via libavformat (FFmpeg)

## Goal

Replace the current extension-only acceptance of `.mov` (and `.mp4`) video files with real container+codec validation using FFmpeg's **libavformat** and **libavcodec**. After this change, corrupt or truncated video files are rejected with `BrokenFile` instead of silently stored.

This is the first **video** validator, upgrading the two formats that `0001.INITIAL` deliberately deferred as "extension-based only" to full structural validation. It also establishes the pattern for any future video format support.

## Background

MOV (QuickTime File Format) and MP4 (MPEG-4 Part 14) are both ISOBMFF-based container formats. They share the same box/atom structure and are often interchangeable — many `.mov` files are valid `.mp4` and vice versa. Apple devices record video as `.mov`; most other devices and web services use `.mp4`.

**libavformat** is FFmpeg's container demuxing/muxing library. It can open a container from a memory buffer (via a custom `AVIOContext`), probe its streams, and read packets. Combined with **libavcodec** for trial decoding, it provides thorough validation of both container structure and codec-level integrity.

The system already has both installed:
- `libavformat-dev` 62.12.100 (FFmpeg 8.x)
- `libavcodec-dev` 62.28.100
- `libavutil-dev` 60.26.100

### Current behavior

`Imager.cpp` has a hardcoded `isVideoExtension()` check that accepts `.mp4` and `.mov` without any validation — the file is hashed and stored directly. This means a completely corrupt file named `video.mov` passes through with `ErrorCode::Ok`.

### Key differences from image validators

| Aspect | Image validators (JPEG/PNG/HEIC) | MOV/MP4 validator (this plan) |
|--------|----------------------------------|-------------------------------|
| Library | Single-purpose (libjpeg/libpng/libheif) | Multi-purpose (FFmpeg libavformat + libavcodec) |
| Container | None or trivial | ISOBMFF box/atom structure |
| Streams | Single image | Multiple streams (video, audio, subtitles) |
| Validation depth | Full pixel decode | Container parse + stream probe + trial frame decode |
| File extensions | Format-specific | `.mov` and `.mp4` (same validator, same container family) |

## Supported extensions

| Extension | Meaning |
|-----------|---------|
| `.mov` | QuickTime container — default video format on Apple devices |
| `.mp4` | MPEG-4 Part 14 container — universal video format |

Both are ISOBMFF-based and handled by the same libavformat demuxer (`mov,mp4,m4a,3gp,3g2,mj2`). A single validator handles both.

## Validation strategy

Validation must confirm that the data is a structurally valid MOV/MP4 container that FFmpeg can demux, that it contains at least one video stream, and that the video codec data is not corrupt. The approach balances thoroughness with performance — video files can be very large (multi-GB), so full decode of every frame is impractical.

### Validation steps

1. **Quick rejection** — check minimum size (8 bytes) and verify ISOBMFF box signature. MOV/MP4 files start with a box whose type (at offset 4) is typically `ftyp`, `moov`, `mdat`, `wide`, or `free`. The `ftyp` box is the most common and reliable indicator. If the first box type is not a recognized ISOBMFF atom type, return `WRONG`.
2. **Open from memory** — construct a custom `AVIOContext` backed by the in-memory buffer, then call `avformat_open_input()` to parse the container structure. This reads the `moov` atom, track atoms, and sample tables. Failure → classify error.
3. **Find streams** — call `avformat_find_stream_info()` to probe the streams and populate codec parameters. This is necessary because some containers have incomplete headers and require reading a few packets to determine stream properties. Failure → `INVALID`.
4. **Verify video stream exists** — iterate over `AVFormatContext::streams` and check that at least one stream has `codecpar->codec_type == AVMEDIA_TYPE_VIDEO`. If no video stream found → `INVALID` (a MOV/MP4 with only audio is not a video file for our purposes).
5. **Trial decode** — find the best video stream, open its codec via `avcodec_open2()`, read a small number of packets (up to 8 video packets or 1 successfully decoded frame, whichever comes first), and attempt to decode them with `avcodec_send_packet()` / `avcodec_receive_frame()`. Successfully decoding at least one frame confirms codec-level integrity. Decode failure → `INVALID`.
6. **Cleanup** — free `AVFrame`, `AVCodecContext`, `AVFormatContext`, `AVIOContext`, and the I/O buffer in reverse order. Return `VALID`.

### Why trial decode instead of full decode?

Full decoding of a video file would mean decoding every frame — minutes of CPU time for a large file. This is impractical and unnecessary for validation:

- **Container parse** (steps 2–4) catches structural corruption: missing moov atom, broken sample tables, invalid track references.
- **Stream probing** catches codec parameter inconsistencies.
- **Trial decode** (step 5) catches codec-level issues: corrupt headers, missing codec-specific extradata, incompatible codec builds. Decoding one frame exercises the full codec initialization and decode pipeline.

A file that passes all these steps is overwhelmingly likely to be valid. Bit-level corruption in the middle of a long video would only affect specific frames and would not be caught by any practical validation short of full decode — this is analogous to how the image validators decode the full image (feasible because images are single frames).

### Memory-backed I/O

libavformat normally reads from files via `avio_open()`. For in-memory validation, a custom `AVIOContext` is constructed:

```cpp
// Buffer and state for the custom AVIO read callback
struct BufferState {
    const uint8_t* data;
    size_t size;
    size_t pos;
};

static int readPacket(void* opaque, uint8_t* buf, int buf_size) {
    auto* state = static_cast<BufferState*>(opaque);
    size_t remaining = state->size - state->pos;
    if (remaining == 0) return AVERROR_EOF;
    size_t toRead = std::min(remaining, static_cast<size_t>(buf_size));
    std::memcpy(buf, state->data + state->pos, toRead);
    state->pos += toRead;
    return static_cast<int>(toRead);
}

static int64_t seekBuffer(void* opaque, int64_t offset, int whence) {
    auto* state = static_cast<BufferState*>(opaque);
    switch (whence) {
        case SEEK_SET: state->pos = static_cast<size_t>(offset); break;
        case SEEK_CUR: state->pos += static_cast<size_t>(offset); break;
        case SEEK_END: state->pos = state->size + static_cast<size_t>(offset); break;
        case AVSEEK_SIZE: return static_cast<int64_t>(state->size);
        default: return AVERROR(EINVAL);
    }
    if (state->pos > state->size) state->pos = state->size;
    return static_cast<int64_t>(state->pos);
}
```

The `AVSEEK_SIZE` case is important — libavformat's MOV demuxer uses it to determine the file size for parsing the `moov` atom, which can be at the end of the file. Without seek support, many MOV files would fail to open.

The AVIO buffer (passed to `avio_alloc_context`) is allocated with `av_malloc()` and its ownership transfers to the `AVIOContext`. The `BufferState` is stack-allocated and valid for the duration of the validation call.

### RAII considerations

FFmpeg's C API uses manual resource management with several interdependent objects. Cleanup must happen in strict reverse order:

1. `av_frame_free(&frame)`
2. `avcodec_free_context(&codecCtx)`
3. `avformat_close_input(&fmtCtx)` — this also frees the `AVIOContext` if `fmtCtx->flags & AVFMT_FLAG_CUSTOM_IO` is set, BUT only if `fmtCtx->pb` was set before `avformat_open_input` was called. In practice, `avformat_close_input` frees the format context but does NOT free the custom AVIO context's buffer or the AVIO context itself when using custom I/O.
4. `av_freep(&avioCtx->buffer)` — free the I/O buffer (only if AVIO was allocated)
5. `avio_context_free(&avioCtx)` — free the AVIO context

To avoid complexity, the implementation uses a cleanup function called at every return point, or a small RAII wrapper struct that handles all resources:

```cpp
struct FFmpegState {
    AVFormatContext* fmtCtx = nullptr;
    AVIOContext* avioCtx = nullptr;
    AVCodecContext* codecCtx = nullptr;
    AVFrame* frame = nullptr;
    AVPacket* pkt = nullptr;
    uint8_t* ioBuffer = nullptr;

    ~FFmpegState() {
        if (pkt) av_packet_free(&pkt);
        if (frame) av_frame_free(&frame);
        if (codecCtx) avcodec_free_context(&codecCtx);
        if (fmtCtx) avformat_close_input(&fmtCtx);
        // After avformat_close_input, avioCtx may still need freeing for custom I/O
        if (avioCtx) {
            // Don't double-free the buffer — avformat_close_input may or may not free it
            // Safe approach: set buffer to nullptr before freeing context
            av_freep(&avioCtx->buffer);
            avio_context_free(&avioCtx);
        }
    }
};
```

### Error classification

| Condition | Validator result | Rationale |
|---|---|---|
| No ISOBMFF box at start | `WRONG` | Not a MOV/MP4 file |
| `avformat_open_input` fails | `INVALID` | Container is corrupt or unsupported |
| `avformat_find_stream_info` fails | `INVALID` | Cannot determine stream properties |
| No video stream found | `INVALID` | Valid container but not a video file |
| Codec not found for video stream | `INVALID` | Video uses unknown/unsupported codec |
| `avcodec_open2` fails | `INVALID` | Codec extradata corrupt or codec misconfigured |
| Trial decode produces no frames | `INVALID` | Video packets present but undecodable |
| At least one frame decoded | `VALID` | Container valid, video stream present, codec works |

## Validation implementation detail

### `mov_validator.cpp`

```cpp
#include "mov_validator.h"

extern "C" {
#include <libavcodec/avcodec.h>
#include <libavformat/avformat.h>
#include <libavutil/avutil.h>
}

#include <cstdint>
#include <cstring>
#include <memory>

namespace {

// ---- Memory-backed I/O for libavformat ----

struct BufferState {
    const uint8_t* data;
    size_t size;
    size_t pos;
};

int readPacket(void* opaque, uint8_t* buf, int buf_size) {
    auto* s = static_cast<BufferState*>(opaque);
    size_t remaining = s->size - s->pos;
    if (remaining == 0) return AVERROR_EOF;
    size_t n = std::min(remaining, static_cast<size_t>(buf_size));
    std::memcpy(buf, s->data + s->pos, n);
    s->pos += n;
    return static_cast<int>(n);
}

int64_t seekBuffer(void* opaque, int64_t offset, int whence) {
    auto* s = static_cast<BufferState*>(opaque);
    int64_t newPos;
    switch (whence) {
        case SEEK_SET: newPos = offset; break;
        case SEEK_CUR: newPos = static_cast<int64_t>(s->pos) + offset; break;
        case SEEK_END: newPos = static_cast<int64_t>(s->size) + offset; break;
        case AVSEEK_SIZE: return static_cast<int64_t>(s->size);
        default: return AVERROR(EINVAL);
    }
    if (newPos < 0) newPos = 0;
    if (newPos > static_cast<int64_t>(s->size)) newPos = static_cast<int64_t>(s->size);
    s->pos = static_cast<size_t>(newPos);
    return newPos;
}

// ---- RAII wrapper for all FFmpeg resources ----

struct FFmpegState {
    AVFormatContext* fmtCtx = nullptr;
    AVIOContext* avioCtx = nullptr;
    AVCodecContext* codecCtx = nullptr;
    AVFrame* frame = nullptr;
    AVPacket* pkt = nullptr;

    ~FFmpegState() {
        if (pkt) av_packet_free(&pkt);
        if (frame) av_frame_free(&frame);
        if (codecCtx) avcodec_free_context(&codecCtx);
        if (fmtCtx) avformat_close_input(&fmtCtx);
        if (avioCtx) {
            av_freep(&avioCtx->buffer);
            avio_context_free(&avioCtx);
        }
    }
};

constexpr size_t kIoBufferSize = 32768;  // 32 KB I/O buffer
constexpr int kMaxPacketsToTry = 8;      // Try up to 8 video packets for trial decode

// Recognized ISOBMFF box types that can appear at the start of a MOV/MP4 file
bool isIsobmffBoxType(const uint8_t* p) {
    // Common leading box types: ftyp, moov, mdat, free, wide, skip, pnot
    static constexpr const char* types[] = {
        "ftyp", "moov", "mdat", "free", "wide", "skip", "pnot"
    };
    for (const auto* t : types) {
        if (std::memcmp(p, t, 4) == 0) return true;
    }
    return false;
}

} // namespace

ValidationResult validateMov(const void* data, size_t dataSize) {
    // Step 1: Quick rejection — check for ISOBMFF box at start
    if (!data || dataSize < 8) return WRONG;
    const auto* bytes = static_cast<const uint8_t*>(data);
    if (!isIsobmffBoxType(bytes + 4)) return WRONG;

    FFmpegState st;
    BufferState buf{bytes, dataSize, 0};

    // Step 2: Set up custom AVIO for memory-backed reading
    auto* ioBuffer = static_cast<uint8_t*>(av_malloc(kIoBufferSize));
    if (!ioBuffer) return INVALID;

    st.avioCtx = avio_alloc_context(
        ioBuffer, kIoBufferSize,
        0,        // write_flag = 0 (read-only)
        &buf,     // opaque
        readPacket, nullptr, seekBuffer
    );
    if (!st.avioCtx) {
        av_freep(&ioBuffer);
        return INVALID;
    }

    st.fmtCtx = avformat_alloc_context();
    if (!st.fmtCtx) return INVALID;
    st.fmtCtx->pb = st.avioCtx;

    int ret = avformat_open_input(&st.fmtCtx, nullptr, nullptr, nullptr);
    if (ret < 0) return INVALID;

    // Step 3: Probe streams
    ret = avformat_find_stream_info(st.fmtCtx, nullptr);
    if (ret < 0) return INVALID;

    // Step 4: Find best video stream
    int videoIdx = av_find_best_stream(
        st.fmtCtx, AVMEDIA_TYPE_VIDEO, -1, -1, nullptr, 0
    );
    if (videoIdx < 0) return INVALID;

    AVStream* videoStream = st.fmtCtx->streams[videoIdx];

    // Step 5: Trial decode — open codec and decode one frame
    const AVCodec* codec = avcodec_find_decoder(videoStream->codecpar->codec_id);
    if (!codec) return INVALID;

    st.codecCtx = avcodec_alloc_context3(codec);
    if (!st.codecCtx) return INVALID;

    ret = avcodec_parameters_to_context(st.codecCtx, videoStream->codecpar);
    if (ret < 0) return INVALID;

    ret = avcodec_open2(st.codecCtx, codec, nullptr);
    if (ret < 0) return INVALID;

    st.frame = av_frame_alloc();
    st.pkt = av_packet_alloc();
    if (!st.frame || !st.pkt) return INVALID;

    bool gotFrame = false;
    int packetsRead = 0;
    while (packetsRead < kMaxPacketsToTry) {
        ret = av_read_frame(st.fmtCtx, st.pkt);
        if (ret < 0) break;  // EOF or error

        if (st.pkt->stream_index != videoIdx) {
            av_packet_unref(st.pkt);
            continue;
        }
        ++packetsRead;

        ret = avcodec_send_packet(st.codecCtx, st.pkt);
        av_packet_unref(st.pkt);
        if (ret < 0) continue;

        ret = avcodec_receive_frame(st.codecCtx, st.frame);
        if (ret == 0) {
            gotFrame = true;
            break;
        }
    }

    return gotFrame ? VALID : INVALID;
}
```

### Thread safety note

FFmpeg's global state (`avcodec_register_all`, `av_register_all`, etc.) is no longer needed as of FFmpeg 4.0+ — codec and format registration is automatic. The functions used here (`avformat_open_input`, `avcodec_open2`, etc.) are thread-safe as long as each thread uses its own contexts, which is the case since the entire validation runs with locally-allocated objects.

No global initialization call is needed.

## Risk: FFmpeg header compatibility (C vs C++)

FFmpeg headers are C headers and must be included inside `extern "C" {}` blocks in C++ code. The implementation file must use:

```cpp
extern "C" {
#include <libavcodec/avcodec.h>
#include <libavformat/avformat.h>
#include <libavutil/avutil.h>
}
```

Some FFmpeg versions have headers that are not fully C++-clean (e.g., using `class` as a variable name in older versions). FFmpeg 8.x (the installed version) is expected to be clean, but if issues arise, the workaround is to create a thin C wrapper file (`mov_validator_ffmpeg.c`) that exposes a simplified C API, called from the C++ validation function.

## Risk: large video files and validation performance

The trial-decode approach (read up to 8 video packets, decode 1 frame) is designed to be fast even for large files. The time is dominated by:
- `avformat_open_input` + `avformat_find_stream_info`: reads the `moov` atom and a few initial packets. For well-formed files with `moov` at the start, this is fast. For files with `moov` at the end (common for streaming-optimized MP4), libavformat seeks to the end — the seek callback handles this via the in-memory buffer.
- `avcodec_open2` + one frame decode: codec initialization + decode of a single keyframe. For H.264/H.265 baseline, this is milliseconds even for 4K.

For the in-memory validation pattern used by this project (the entire file is already in a `Blob`), seek performance is O(1) since it's just a pointer adjustment. No actual I/O is involved.

## Comparison with existing system-library patterns

| Aspect | HEIC (0007) | NEF (0008) | MOV (this plan) |
|--------|-------------|------------|-----------------|
| System library | `libheif-dev` | `libraw-dev` | `libavformat-dev` + `libavcodec-dev` + `libavutil-dev` |
| CMake discovery | `find_package(libheif)` | `pkg_check_modules(libraw)` | `pkg_check_modules(libavformat)` + 2 more |
| Number of deps | 1 | 1 | 3 (format, codec, util) |
| Memory I/O | `heif_context_read_from_memory_without_copy` | `libraw_open_buffer` | Custom `AVIOContext` with read/seek callbacks |
| Validation depth | Container + full decode | Parse + unpack (no demosaic) | Container + stream probe + trial decode (1 frame) |
| RAII complexity | 3 resource types | 1 resource type (unique_ptr) | 5-6 resource types (struct wrapper) |

The MOV validator is the most complex due to FFmpeg's multi-layered API, but the pattern is the same: system library, pkg-config discovery, RAII cleanup, `WRONG`/`INVALID`/`VALID` classification.
