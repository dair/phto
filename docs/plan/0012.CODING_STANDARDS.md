## 4. Implementation Sequence

Work is grouped into six phases. Phases are sequential; within each phase, independent items can proceed in parallel.

### Phase 1 — Resolve SQLite ambiguity (C2)

**Goal**: Establish ground truth on whether SQLite is bundled or system.

**Decision needed**:
- Option A: SQLite is a **system** dependency (already the de-facto behavior). Update `CLAUDE.md` and `database/CLAUDE.md` to say "system dependency via `find_package(SQLite3)`". Remove contradictory "bundle" language.
- Option B: Bundle SQLite. Add `database/sqlite/src/sqlite3.c` + `database/sqlite/src/sqlite3.h`, write a `database/sqlite/CMakeLists.txt` that produces a `sqlite3` static library, and replace `find_package(SQLite3)` in `database/CMakeLists.txt` with `add_subdirectory(sqlite)`.

**Recommended**: Option A (system dependency) — the source tree has never had the bundled SQLite, the build already uses system SQLite successfully, and bundling it would add ~250 KB of vendored C code. Document the decision explicitly.

**Deliverables**: Updated `database/CMakeLists.txt` comment (if Option A, no code change; just CLAUDE.md). If Option B, new `database/sqlite/` tree and updated CMakeLists.

**Agent**: `cpp-spec-coder` (or direct edit; very small)

### Phase 2 — Metrics singleton removal (C3) + move-delete (H4, partial)

**Goal**: Remove `Metrics::get()` singleton; thread `Metrics` as an injected dependency.

**Detailed steps**:

1. **`metrics/Metrics.h`**:
   - Remove `static Metrics& get()` declaration.
   - Add `Metrics(Metrics&&) = delete; Metrics& operator=(Metrics&&) = delete;` (covers H4 for Metrics).
   - `Metrics` becomes a plain value type — no singleton constructor.

2. **`metrics/Metrics.cpp`**:
   - Remove the `get()` implementation.

3. **`imager/Imager.h` / `imager/Imager.cpp`**:
   - `Imager::Impl` acquires a `metrics::Metrics` member (owns the instance).
   - All internal code that called `metrics::Metrics::get().foo` now uses `m_metrics.foo`.
   - Pass `m_metrics` by reference into `FileStorage` and `MultiDatabase` constructors.

4. **`imager/FileStorage.h` / `imager/FileStorage.cpp`**:
   - Add `metrics::Metrics& m_metrics` member.
   - Constructor receives `metrics::Metrics&` parameter.
   - All `Metrics::get().foo` → `m_metrics.foo`.

5. **`imager/MultiDatabase.h` / `imager/MultiDatabase.cpp`**:
   - Same pattern: add `metrics::Metrics& m_metrics`, thread through constructor.

6. **`imagestore/main.cpp`**:
   - `imagestore` currently calls `Metrics::get()` to snapshot metrics at the end.
   - After refactor, `Imager` (or a new `Imager::metrics()` accessor) exposes the `Metrics` reference.
   - Update `imagestore/main.cpp` to obtain the `Metrics` reference from the `Imager` object.

**Deliverables**: `Metrics` with no `get()`, all callers updated, build still passes.

**Agent**: `cpp-spec-coder` (significant refactor — 3–4 files touched deeply)

### Phase 6 — Add `-Werror` to all targets (C1)

**Goal**: Enforce warning-as-error across all first-party targets. This is placed last so that prior fixes eliminate any warnings that would immediately break the build.

Two implementation options:

**Option A (global)**: In root `CMakeLists.txt`, add:
```cmake
if(CMAKE_CXX_COMPILER_ID MATCHES "Clang|GNU")
  add_compile_options(-Werror)
endif()
```

**Option B (per-target, surgical)**: Add `-Werror` to each existing `target_compile_options` call across all 12 affected CMakeLists files.

**Recommended**: Option A (global) — simpler, consistent, and aligned with CODING.md intent ("all first-party targets"). Third-party FetchContent targets are not first-party and are unaffected by `add_compile_options` in the root (they typically define their own options).

**Pre-condition**: Full build must be warning-clean after Phases 1–5 before `-Werror` is added.

**Deliverables**: Clean build with `-Werror` enabled.

**Agent**: `cpp-spec-coder` + `testing-engineer-agent` to verify build
