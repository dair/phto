# Plan 0020 — Preserve Original File Timestamps

## 1. Requirement

When the imager tool stores a file (writes it to a storage root), the resulting stored file MUST carry the same timestamps as the original source file. Specifically:

- **mtime** (last-modification time) — mandatory; always preserved.
- **atime** (last-access time) — mandatory; preserved alongside mtime via a single syscall.
- **ctime** (last-status-change time on POSIX) — cannot be set by any unprivileged process on Linux/macOS; it is always reset to "now" by the kernel on any write or `utimes`/`utimensat` call. This is accepted and documented as a known limitation.
- **birthtime** (creation time, macOS/Windows) — preserved on macOS via `setattrlist(2)` as a best-effort operation; not attempted on Linux (ext4/btrfs expose birthtime read-only, no standard POSIX API to set it for unprivileged users).

The feature applies only to the **file-from-disk ingestion path** (`addFile` / `writeFileFromDiskAsync`). The blob ingestion path (`addImage`) never has an on-disk source file, so there is nothing to copy from.

---

## 2. Platform Considerations

| Platform | mtime / atime API | ctime | birthtime |
|---|---|---|---|
| Linux | `utimensat(2)` with nanosecond precision | Kernel-only; cannot be set | Not settable by userspace on ext4/xfs/btrfs |
| macOS | `utimensat(2)` (same API) or `futimens(3)` | Kernel-only | `setattrlist(2)` — best-effort, silently ignored on failure |
| Windows | `SetFileTime()` via Win32 API | Kernel-managed | Settable via `SetFileTime` | 

This project is **Linux-primary**. macOS best-effort birthtime and Windows are out of scope for this plan iteration. The implementation will use `utimensat(2)` (POSIX.1-2008), which is available on both Linux and macOS and provides nanosecond granularity. No conditional compilation is needed for the mandatory mtime/atime preservation.

### Sub-second precision notes

- `utimensat` accepts `struct timespec` (nanoseconds); on filesystems that only store whole seconds (FAT32, some NFS configurations), the kernel silently rounds or truncates. The implementation does not need to handle this — the syscall succeeds, the filesystem does the best it can.
- FAT32 has 2-second mtime granularity and no atime beyond the date. This is a filesystem limitation, not a bug in the implementation.

## 3. Where Timestamps Must Be Applied

### 3.1 Entry points into file-writing

All file writes ultimately go through `FileStorage` in `/home/vibe/imager/imager/imager/FileStorage.cpp`. There are two leaf coroutines that actually write bytes to disk:

1. **`FileStorage::writeToRoot`** — writes a `Blob` (in-memory bytes) to a single storage root.  
   Called from `writeFileAsync` (blob ingest path, `addImage`).  
   No source path is available here. **No timestamp action needed.**

2. **`FileStorage::writeToRootFromDisk`** — stream-copies from a `sourcePath` to a single storage root.  
   Called from `writeFileFromDiskAsync` (disk ingest path, `addFile` / `addFileLarge`).  
   **This is the correct hook point.** After the streaming copy completes and before `co_return`, apply `utimensat` to copy source timestamps to the destination.

3. **`FileStorage::relocateFileAsync`** — renames/copies a stored file to a new storage path (used for sidecar orphan resolution).  
   When `std::filesystem::rename` succeeds, timestamps are preserved atomically by the kernel (rename does not touch timestamps). When it falls back to `copy_file + remove`, the destination gets current timestamps. **Apply timestamp preservation in the copy+delete branch only**, after `copy_file` succeeds.

### 3.2 Summary table

| Write path | Hook needed? | Location |
|---|---|---|
| `writeToRoot` (blob) | No — no source mtime | `FileStorage.cpp` |
| `writeToRootFromDisk` (disk copy) | **Yes** | After streaming loop, before `co_return` |
| `relocateFileAsync` (rename) | No — rename preserves timestamps | `FileStorage.cpp` |
| `relocateFileAsync` (copy+delete fallback) | **Yes** | After `copy_file`, before `remove` |

## 4. New Utility: `FileTimestamp`

Introduce a new header-only utility:

```
/home/vibe/imager/imager/imager/FileTimestamp.h
```

### 4.1 API

```cpp
namespace imager {

/// Read mtime and atime from sourcePath and apply them to destPath.
/// Uses utimensat(2) for nanosecond precision on Linux/macOS.
/// On failure: throws std::system_error with errno details.
/// On a filesystem that cannot store sub-second precision, the
/// syscall still succeeds (the FS truncates silently).
///
/// This function is a no-op stub on platforms where _POSIX_VERSION < 200809L.
void copyTimestamps(
    const std::filesystem::path& sourcePath,
    const std::filesystem::path& destPath
);

} // namespace imager
```

### 4.2 Implementation approach

```cpp
#include <sys/stat.h>   // stat, struct timespec
#include <fcntl.h>      // AT_FDCWD
#include <cerrno>
#include <system_error>

void copyTimestamps(
    const std::filesystem::path& sourcePath,
    const std::filesystem::path& destPath
) {
    struct stat st{};
    if (::stat(sourcePath.c_str(), &st) != 0) {
        throw std::system_error(errno, std::system_category(),
            "stat failed: " + sourcePath.string());
    }
    struct timespec times[2];
    // times[0] = atime, times[1] = mtime
#ifdef __linux__
    times[0] = st.st_atim;   // struct timespec, nanoseconds
    times[1] = st.st_mtim;
#else
    // macOS / BSD: st_atimespec / st_mtimespec
    times[0] = st.st_atimespec;
    times[1] = st.st_mtimespec;
#endif
    if (::utimensat(AT_FDCWD, destPath.c_str(), times, 0) != 0) {
        throw std::system_error(errno, std::system_category(),
            "utimensat failed: " + destPath.string());
    }
}
```

`utimensat` with `AT_FDCWD` and flag `0` resolves the path relative to the current working directory (same as `utimes`) and does not follow symlinks differently. If `destPath` is an absolute path, `AT_FDCWD` is irrelevant.

## 5. Changes to `FileStorage.cpp`

### 5.1 `writeToRootFromDisk` — add timestamp copy after streaming loop

After the streaming write succeeds and before the coroutine returns, insert:

```cpp
// Preserve original file timestamps (mtime + atime).
// Errors here are non-fatal by design — the file content is fully written.
// We rethrow so the caller can decide; the file is already on disk.
copyTimestamps(sourcePath, destPath);
```

The call goes **after** the `if (in.bad())` guard (i.e., after we know content is correct) and **before** `co_return` (implicit).

### 5.2 `relocateFileAsync` — copy+delete fallback branch

After the `copy_file` call succeeds and before `remove(oldPath)`, insert:

```cpp
// Preserve timestamps from old path to new path after cross-device copy.
try {
    copyTimestamps(oldPath, newPath);
} catch (...) {
    // Best-effort; don't fail relocation because of timestamp errors.
}
```

Note: in the copy+delete fallback, `oldPath` still exists at this point (it is removed only after), so reading its timestamps is safe.

## 7. Edge Cases

| Edge case | Behaviour |
|---|---|
| Source is a symlink | `stat()` follows the symlink; we copy the symlink's target's timestamps to `destPath`. This is correct — the stored file is a regular file. |
| Destination is a symlink | `utimensat(..., 0)` without `AT_SYMLINK_NOFOLLOW` follows the symlink. Stored files are always regular files (not symlinks), so this is safe. |
| Source file disappears between copy and stat | `stat()` fails → `std::system_error` thrown. The blob content is already stored; whether to roll back is caller's responsibility. The current implementation will let the exception propagate to `writeFileFromDiskAsync`'s error path, which triggers rollback (same as any other write failure). |
| Permission denied on `utimensat` | Only the file owner or root can set arbitrary timestamps on Linux. Since imager writes the file itself (it is the creator), the POSIX permission check passes. Edge case: NFS with squash_root. Wrapped in `std::system_error`; propagates to caller. |
| Read-only filesystem | `utimensat` will fail with `EROFS`. Exception propagates. |
| FAT32 / 2-second granularity | `utimensat` succeeds; FS truncates to nearest 2-second boundary. Acceptable. |
| NFS with `noatime` | `utimensat` on atime is silently ignored by the server. Acceptable. |
| Clock skew (source timestamp in the future) | `utimensat` accepts any `timespec`; no validation needed. |

## 8. Testing Strategy

### 8.1 Unit tests — `FileStorage` level (C++ / CPPUnit)

Add a new test suite `TimestampPreservationTest` to `/home/vibe/imager/imager/imager/test/ImagerTest.cpp` (or a new file `TimestampTest.cpp` added to the CMakeLists).

Test cases:

1. **Basic mtime/atime preservation** — Create a source file, set its timestamps to a known past value (e.g., 2020-01-01 00:00:00 UTC) using `utimensat`, call `addFile(path)`, read the stored file's `stat`, assert stored mtime == source mtime (within 1 second to tolerate FAT32 on CI).
2. **Nanosecond precision** — Set source timestamps to a value with non-zero nanoseconds (e.g., `tv_nsec = 123456789`), call `addFile`, assert stored mtime nanoseconds match (skip assertion if running on a non-nanosecond-capable FS by checking `_PC_TIMESTAMP_RESOLUTION`).
3. **Multi-root** — Two storage roots; assert both stored copies carry the same mtime as the source.
4. **Large file (streaming path)** — Use a source file exceeding the streaming threshold (or inject a mock threshold) and verify timestamps are preserved.
5. **Sidecar relocation (rename path)** — Add an orphan AAE then its parent; verify the relocated sidecar has the correct mtime. (The rename path preserves timestamps natively; this test validates no regression.)
6. **Sidecar relocation (copy+delete path)** — Force the copy+delete fallback by using a cross-device scenario (tmpfs to ext4, or mock `rename` failing). Verify timestamp preservation. (Can be tested at the `FileTimestamp` unit level directly.)
7. **`copyTimestamps` unit test** — Direct test of the helper: write a temp file, set known timestamps, call `copyTimestamps(src, dst)`, stat both, assert equal.
8. **Permission error handling** — Chmod dest directory to 555, call `addFile`, expect `StorageError` (write fails before timestamp step). This documents that timestamp errors propagate as `StorageError`.

### 8.2 Shell CLI tests (imagestore)

Add to `/home/vibe/imager/imager/imagestore/test/test_cli.sh.in`:

- Import a file, capture mtime of source with `stat --format %Y` (epoch seconds), look up stored path via `sqlite3`, stat that path, assert mtimes are equal.

### 8.3 CI / environment notes

- All tests run in `/tmp/` (tmpfs on Linux). tmpfs supports nanosecond timestamps, so the nanosecond test can be enabled unconditionally on the CI host.
- Tests must be idempotent and clean up temp directories in `tearDown()`.
