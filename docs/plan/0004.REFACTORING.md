# 0004 — Type Splitting & Library Extraction

## Goal

Two structural refactorings with **no changes to functionality**:

1. **Split `Types.h`** — move each type (`ErrorCode`, `ImageInfo`, `AddResult`) into its own file under `types/`, matching `Blob.h` which is already there. `Types.h` becomes a convenience umbrella header.

2. **Extract two generic libraries** — `coro/` and `Blob` have zero project-specific dependencies and are reusable. Move them to top-level libraries alongside `database/` and `config/`.

## Part 1: Split Types.h into individual files

### Current state

```
imager/include/imager/
├── Types.h          # ErrorCode, ImageInfo, AddResult + #include "types/Blob.h"
├── Imager.h         # includes Types.h
├── ImageValidator.h
└── types/
    └── Blob.h       # already separated
```

### Target state

```
imager/include/imager/
├── Types.h          # umbrella: includes all four types/* headers
├── Imager.h         # includes Types.h (unchanged)
├── ImageValidator.h
└── types/
    ├── Blob.h       # unchanged
    ├── ErrorCode.h  # NEW — enum class ErrorCode
    ├── ImageInfo.h  # NEW — struct ImageInfo
    └── AddResult.h  # NEW — struct AddResult (includes ErrorCode.h)
```

### New files

#### `types/ErrorCode.h`

```cpp
#pragma once

namespace imager {

enum class ErrorCode {
    Ok,
    BrokenFile,
    DuplicateFile,
    UnsupportedFormat,
    FileNotFound,
    StorageError,
    DatabaseError,
    ConfigError
};

} // namespace imager
```

No includes needed — pure enum.

#### `types/ImageInfo.h`

```cpp
#pragma once

#include <cstdint>
#include <string>
#include <vector>

namespace imager {

struct ImageInfo {
    std::string              id;
    std::string              name;
    uint64_t                 size{0};
    std::string              ext;
    std::vector<std::string> tags;
};

} // namespace imager
```

No dependency on other project types.

#### `types/AddResult.h`

```cpp
#pragma once

#include "ErrorCode.h"

#include <string>

namespace imager {

struct AddResult {
    ErrorCode   code{ErrorCode::Ok};
    std::string id;
    std::string message;
};

} // namespace imager
```

Depends on `ErrorCode.h` (same directory — relative include works).

#### Updated `Types.h` (umbrella)

```cpp
#pragma once

#include "types/Blob.h"
#include "types/ErrorCode.h"
#include "types/ImageInfo.h"
#include "types/AddResult.h"
```

No namespace, no types — just includes. Every existing consumer that does `#include "imager/Types.h"` continues to work unchanged.

### Files modified

| File | Change |
|------|--------|
| `imager/include/imager/Types.h` | Replace type definitions with four `#include` directives |

### Files NOT modified

Every file that currently includes `Types.h` (directly or via `Imager.h`) keeps working because `Types.h` still re-exports everything. No source file, test, or sample needs changes.

Consumers that only need `ErrorCode` (not the full `Types.h`) can later switch to `#include "imager/types/ErrorCode.h"` for faster compilation, but this is optional and not part of this refactoring.

## Part 2: Extract `coro/` as a top-level library

### Rationale

The coroutine infrastructure (`Task<T>`, `ThreadPool`, `WhenAll`, `BlockOn`) is:
- Pure C++23 with zero project-specific dependencies
- Self-contained (no includes outside `<coroutine>`, `<thread>`, `<mutex>`, etc.)
- Currently in the `imager::coro` namespace, living under `imager/src/coro/`
- Reusable by any C++23 project

### Current location

```
imager/src/coro/
├── Task.h
├── ThreadPool.h
├── WhenAll.h
└── BlockOn.h
```

All header-only except `ThreadPool` which is also header-only (implementation in the header).

### Target location

```
coro/                           # NEW top-level library
├── CMakeLists.txt              # header-only INTERFACE library
└── include/
    └── coro/
        ├── Task.h
        ├── ThreadPool.h
        ├── WhenAll.h
        └── BlockOn.h
```

### Namespace change

The namespace changes from `imager::coro` to `coro`:

```cpp
// Before:
namespace imager::coro { ... }

// After:
namespace coro { ... }
```

This is a find-and-replace across the four coro headers and all consumers.

### CMake setup

#### `coro/CMakeLists.txt`

```cmake
add_library(coro_lib INTERFACE)
target_include_directories(coro_lib INTERFACE
    "${CMAKE_CURRENT_SOURCE_DIR}/include"
)
```

Header-only — no source files to compile.

#### Top-level `CMakeLists.txt` change

Add `add_subdirectory(coro)` before `add_subdirectory(imager)`.

#### `imager/CMakeLists.txt` changes

- Remove `"${CMAKE_CURRENT_SOURCE_DIR}/src/coro"` from `target_include_directories PRIVATE`
- Add `coro_lib` to `target_link_libraries`
- All coro includes change from `"coro/Task.h"` (relative, private) to `<coro/Task.h>` or `"coro/Task.h"` (via the public include path from `coro_lib`)

### Files modified

| File | Change |
|------|--------|
| `coro/Task.h` | Namespace `imager::coro` → `coro` |
| `coro/ThreadPool.h` | Namespace `imager::coro` → `coro` |
| `coro/WhenAll.h` | Namespace `imager::coro` → `coro` |
| `coro/BlockOn.h` | Namespace `imager::coro` → `coro` |
| `imager/src/MultiDatabase.h` | Include path unchanged (still `"coro/Task.h"`); namespace refs `coro::Task`, `coro::ThreadPool` (drop `imager::` prefix) |
| `imager/src/MultiDatabase.cpp` | Namespace refs `coro::blockOn`, `coro::whenAll` (drop `imager::` prefix) |
| `imager/src/FileStorage.h` | Same include/namespace changes |
| `imager/src/FileStorage.cpp` | Same |
| `imager/src/Imager.cpp` | Same |
| `imager/CMakeLists.txt` | Remove private coro include dir; add `coro_lib` link |
| `CMakeLists.txt` (top-level) | Add `add_subdirectory(coro)` |

### Files NOT modified

- `imager/include/imager/Imager.h` — does not reference coro types (they are internal)
- All test and sample files — they use `Imager` facade, not coro directly
- `database/`, `config/`, `validations/` — no coro dependency

### Namespace impact

Since the coro types only appear in internal files (`MultiDatabase.h/cpp`, `FileStorage.h/cpp`, `Imager.cpp`), the namespace change from `imager::coro::` to `coro::` affects **no public API**. Consumers of `libimager` never see coro types.

## Part 3: Extract `Blob` as a top-level library

### Rationale

`Blob` is:
- A generic shared-ownership binary buffer
- Header-only, zero dependencies beyond `<cstdint>`, `<cstring>`, `<memory>`, `<vector>`
- Currently in the `imager` namespace under `imager/include/imager/types/Blob.h`
- Used by: `Hasher.h`, `FileStorage.h`, `Imager.h` (via `Types.h`), tests, sample

### Current location

```
imager/include/imager/types/Blob.h    # namespace imager
```

### Target location

```
blob/                                  # NEW top-level library
├── CMakeLists.txt                     # header-only INTERFACE library
└── include/
    └── blob/
        └── Blob.h                     # namespace blob
```

### Namespace change

```cpp
// Before:
namespace imager { class Blob { ... }; }

// After:
namespace blob { class Blob { ... }; }
```

### Convenience alias in imager

To avoid changing every call site in the imager codebase, add a type alias:

```cpp
// imager/include/imager/types/Blob.h (kept as a thin forwarding header)
#pragma once
#include <blob/Blob.h>
namespace imager { using blob::Blob; }
```

This means:
- All existing code using `imager::Blob` or just `Blob` (inside `namespace imager`) continues to compile unchanged
- New code outside imager can use `blob::Blob` directly
- The original `types/Blob.h` file becomes a one-line forwarding header

### CMake setup

#### `blob/CMakeLists.txt`

```cmake
add_library(blob_lib INTERFACE)
target_include_directories(blob_lib INTERFACE
    "${CMAKE_CURRENT_SOURCE_DIR}/include"
)
```

#### Top-level `CMakeLists.txt`

Add `add_subdirectory(blob)` before `add_subdirectory(imager)`.

#### `imager/CMakeLists.txt`

Add `blob_lib` to `target_link_libraries PUBLIC` (since `Blob` is part of the public API via `Types.h`).

### Files modified

| File | Change |
|------|--------|
| `blob/include/blob/Blob.h` | **New file**: move Blob class here, namespace `blob` |
| `blob/CMakeLists.txt` | **New file**: INTERFACE library |
| `imager/include/imager/types/Blob.h` | Replace class with forwarding header: `#include <blob/Blob.h>` + `using blob::Blob` |
| `imager/CMakeLists.txt` | Add `blob_lib` to link libraries |
| `CMakeLists.txt` (top-level) | Add `add_subdirectory(blob)` |

### Files NOT modified

- `imager/include/imager/Types.h` — still does `#include "types/Blob.h"`, which now forwards
- `imager/src/Hasher.h` — still does `#include "imager/types/Blob.h"`, gets Blob via forwarding
- `imager/src/FileStorage.h` — same
- `imager/src/Imager.cpp`, all tests, sample — `imager::Blob` alias works transparently
- No source file changes needed thanks to the alias

## Implementation order

1. **Part 1: Split Types.h** — create `types/ErrorCode.h`, `types/ImageInfo.h`, `types/AddResult.h`; turn `Types.h` into umbrella
2. **Part 2: Extract coro/** — create `coro/` top-level lib; move headers; update namespace and includes
3. **Part 3: Extract Blob** — create `blob/` top-level lib; move class; leave forwarding header + alias
4. Build and verify all tests pass

Parts 1, 2, and 3 are independent of each other and can be done in any order, but the listed order minimizes intermediate breakage (Part 1 is purely additive, Part 2 only touches internal files, Part 3 touches the public include path).
