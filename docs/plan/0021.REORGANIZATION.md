## 3. Problems

1. **Triple-nested `imager` naming.** A path such as
   `imager/imager/imager/Imager.cpp` is the workspace → project → facade module.
   The repeated name makes paths ambiguous in logs, `cd`, and tab-completion.

2. **Stray build artifacts in the tree.** `CMakeFiles/CMakeSystem.cmake` at the
   workspace root is the residue of a `cmake` invocation run in the wrong
   directory. It is not part of any preset (the project builds into
   `build/imager-build`) and should never have landed here.

3. **Agent run-logs duplicated in two places.** `docs/logs/` (workspace) and
   `imager/docs/logs/` (project) both hold `debugger.md`, `orchestrator.md`,
   `test-writer.md` — and the copies **differ**. There is no single source of
   truth for "what the agents did."

4. **~~Hooks misplaced~~ — RESOLVED.** A `hooks/` directory sat at the workspace
   root (`hook-permission.py`, `sample.json`, and a typo-named `\` file). It was
   never wired into `settings.local.json` and nothing referenced it, so it was
   inert. It has been **deleted**. Its `\` file held a hardcoded Telegram bot
   token, but the file was only ever local (never pushed or exposed outside this
   machine/agent), so this is a cleanup, not an incident. Token rotation is
   optional and at the user's discretion (see §6).

5. **Empty `.codex` marker files** appear at both the workspace root and the
   project root, plus an empty `claude/worktrees/`. Leftover scaffolding.

6. **Stale & over-broad permissions.** `claude/settings.local.json` allow-lists
   paths from a *previous* location — e.g. `/home/vibe/src/phto/imager/...` —
   confirming the project was moved/renamed to `imager`. It also contains very
   broad entries (`Bash(cat)`, `Bash(echo *)`, `Bash(grep *)`, `Bash(awk *)`)
   that defeat the purpose of an allow-list.

7. **A 5 MB test fixture loose at the root.** `sample.NEF` sits at the workspace
   root, detached from the validators. **RESOLVED:** it is byte-for-byte
   identical (`cmp` → IDENTICAL, 5,383,092 bytes) to the existing NEF fixture
   `imager/validations/nef/test/fixtures/valid.nef`, which the decoder tests
   already load in `setUp()`. The root copy is a pure duplicate → **delete it**;
   no move or test wiring required.

## 4. Recommended target layout

**DECIDED:** `imager/` is a shareable, publishable artifact, so its git history
must stay clean. **Option B is adopted** — keep the two repos separate and tidy
each in place. Option A (flatten into one repo) is **rejected** for this project;
it is retained below only as discarded context. See §9 for the rationale.

│       └── (BASELINE.md, LEAKING.md, …)

Changes:

  (rename `claude/` → `.claude/`), so the conventional path is the real one.
- Delete `CMakeFiles/`, both empty `.codex` files, and empty `claude/worktrees/`.
- Pick **one** home for agent run-logs (proposal: project `imager/docs/logs/` is

*Not pursued.* Promoting the project to be the workspace root would remove the
triple-`imager` nesting (§3.1) but requires folding the workspace into the
project's git history — unacceptable for a publishable artifact. Kept here only
to document why flattening was considered and dropped. The triple-`imager`
naming (§3.1) is therefore accepted as-is.

## 9. Git-repo boundary — DECIDED: two repos stay separate

**Decision:** `imager/` is a shareable, publishable artifact, so it keeps a clean
git history of its own. The workspace **does not** become one all-in-one repo;
the Claude scaffolding stays out of the project's history.

**Why.** "One repo for everything" would require flattening the project up so the
workspace root becomes the repo (a parent dir cannot be tracked by a repo living
in a child subdir). That would fold agent memory, local settings, and run-logs
into the project's history and require merging two separate histories — both
unacceptable for something meant to be published.

**Resulting boundary:**

| Lives in                        | Tracked by                  | Contains                                  |
|---------------------------------|-----------------------------|-------------------------------------------|
| `imager/`                       | the **project** repo (keep) | source, design docs, project run-logs     |
| `claude/` → `.claude/`          | the **claude** repo (keep)  | agent definitions, settings, workspace logs |
| workspace root (everything else)| **untracked**               | strays to delete; optional `fixtures/`    |

- Keep both `.git` directories. The project repo never sees Claude tooling.
- In the `.claude/` repo, `.gitignore` the ephemeral/local bits
  (`agent-memory/`, `settings.local.json`, `worktrees/`); track durable things
  (agent definitions, curated logs).
- Nothing at the workspace root needs version control — it is just the container
  holding the two repos side by side.

No further decision required here; proceed with Option B cleanup (§7).
